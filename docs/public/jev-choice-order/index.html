训练「选项顺序不变性」进 Jev 模型
——给因果语言模型动的一次矫正手术

同一道题、同样的选项，只是换了个排列顺序，模型的答案就翻了。这篇交互式笔记拆解 AVB 的长文 《Training choice-order invariance into JEV models》：bug 出在哪、为什么 BERT 救不了、以及两把手术刀——位置编码重置与注意力掩码图。

TL;DR
  • Jev 这类 System One 模型吃进「上下文 + 一组候选选项」，一次前向传播直接吐出每个选项的概率——不逐 token 生成。
  • 但它微调自因果语言模型，后面的选项能「看到」前面的选项（注意力），而且位置编码随顺序改变——换个排序，答案就翻。
  • 修复 = 同时 hack 两样东西：① 每个「选项」的位置 ID 重新计数（都以为自己紧跟在问题后面）；② 注意力掩码剪掉选项之间的边（保持因果性不破坏）。
  • 作者用 Qwen3-0.6B 前 20 层 + LoRA + 700 万参数决策头，训出 bev-decider-0.4B，配套 27.6 万条数据开源。

STATION 02

顺序 bug：换个排序，答案就翻

原文作者观察到的现象：同一道题、同样的选项，只是把选项的左右位置互换，Jev 的答案就变了。下面复现这个现象——你来当那个「换顺序的手」。

工单路由实验 概率为教学模拟，复现原文描述的现象

上下文（工单）：「用户报告：应用在导出 PDF 时崩溃，附了堆栈跟踪。」
正确路由：🐞 Bug 报告处理（工单明说了「崩溃」）。

👇 点击两个选项卡可以交换它们的位置（先点一个，再点另一个）。

对照组 A：普通因果 LM 微调（顺序敏感）

对照组 B：本文的不变模型（顺序无关）

💡 为什么这很严重：一个「正确答案取决于选项排列顺序」的分类器，没法放进任何生产管线——上游系统怎么拼接选项，居然在影响下游的决策。而且这不是 Jev 独有：任何在因果 LM 上微调出来的「选项打分器」都带着这个胎记。原文用词很谨慎：「很可能（likely）因为 Jev 微调自因果语言模型」。
STATION 03

元凶：因果注意力

因果语言模型的每个 token 只能「看见」它前面的 token——这是下一 token 预测的支柱。但当选项们排成一列进序列，后面的选项就偷看了前面的选项。

谁看到了谁？点击任意 token 14-token 示意序列

序列结构 = 问题 + 选项A + 选项B + 选项C + 答案提示。点一个 token，亮起的是它能看到的。

🚨 特权信息泄漏！这个 token 属于某个选项，但它能「看到」排在它前面的其他选项——在真实打分场景里，这相当于选项 B 答题前偷瞄了选项 A 的卷子。原文的原话：「现实的织物被 fcked 了（the fabric of reality is fcked）」。

因果性：下一 token 预测的支柱

位置 10 的 token 只能对 0–9 做 attention；每个 token 的表示完全由过去决定，而这个表示恰好被拿来预测未来。训练目标本身要求信息只能单向流动。

所以这不是 bug，是因果 LM 的设计本意——只是把它拿来做「选项打分」时，本意变成了漏洞。

泄漏是怎么发生的

把 context choice-1 choice-2 choice-3 排进因果序列：

  • choice-1 看到：问题
  • choice-2 看到：问题 + choice-1
  • choice-3 看到：问题 + choice-1 + choice-2

越靠后的选项「知道」得越多——它们的隐藏状态从出生就不平等。

STATION 04

BERT 为什么也救不了

直觉方案：换成双向模型（BERT / ModernBERT），每个 token 都能看到所有 token，总该平等了吧？——不够。因为还有第二个泄密者：位置编码。

实验台：双向注意力 + 换序 交互示意

先打开「双向注意力」开关，再点 token 试试；然后点「交换 B / C」看下面发生什么。

只修注意力？❌

双向化后每个选项都能看到其他选项——至少「平等」了。但每个 token 的隐藏状态里还掺着位置编码：它在序列里排第几，一眼就被出卖。

只做数据增强？⚠️

训练时把选项顺序随机打乱（age-old 老办法）确实能缓解，让模型「见过各种排列」。但这是统计层面的补丁，并不从机制上让模型对顺序不敏感——机制性的偏置还在。

真正要做的 ✅

让「无论选项怎么排，每个选项的表示都一模一样」。要动的是两处根基：位置编码 + 注意力掩码——接下来两站各讲一把手术刀。
STATION 05

手术刀 ①：位置 ID 重置

每个选项都该以为自己「紧跟在问题后面」——因为在模型眼里，问题后面第一个位置，就是它唯一合法的出生地。

位置 ID 编辑器 token 下方数字 = 位置编码 ID

标准模式：位置 ID 从头数到尾，顺序即身份。

原文的做法

  • 问题 token：正常计数 0, 1, 2 …
  • 每个选项：都从「问题结束后的第一个位置」重新开始数——选项 A、B、C 拿到完全相同的位置 ID
  • 答案 token：在选项之后继续计数

从每个选项自己的视角看，它永远紧跟在问题后面——位置这一维度，再也区分不出「谁先谁后」。

副作用：答案 token 会「晕」

打开重置后，三个选项在位置轴上完全重叠；答案 token 要「在选项之后继续数」，等于要求它把一堆互相重叠的东西看作依次排开——很反直觉。

原文态度：确实晕，但 LoRA 微调后模型能恢复。手术有代价，可控。

STATION 06

手术刀 ②：注意力掩码即图

注意力掩码的本质是一张图：节点是 token，边是「允许看」。既然选项之间的边是泄漏通道——那就直接剪断。

掩码矩阵切换器 行 = 看的人，列 = 被看的对象

允许看（颜色=对方所属段） 禁止看 特权泄漏（标准掩码独有） 点击行首的行号可查看该 token 的视野

本文掩码的三条规则 出自原文

  • 问题 token：照常因果——只看自己前面的
  • 每个选项 token：只看「整个问题 + 本选项内部的过往」，绝不看其他选项
  • 答案 token：看全部

关键：依然是因果的

这套掩码没有破坏因果性——每个 token 依然只往前看，只是选项之间的边被剪掉了。Qwen 不需要学习一种全新的注意力范式，预训练的功夫全保得住。

这正是「能移植就不重训」路线能走通的前提。

⚠️ 原文的免责声明：以上分析假设模型使用标准的全注意力（full attention）。现代模型若混用滑动窗口注意力（sliding window）或线性注意力（如 Qwen3.5 混合 Gated DeltaNet），控制 token 可见性会困难得多。
STATION 07

组装一台 0.4B 决策模型

不从头训——直接「移植」：取一个预训练好的语言模型（原文建议：预训练之后、RL 之前的阶段），切掉顶层，接一个轻量决策头。

双编码器（bi-encoder）

状态/问题与每个选项分别编码，用对比损失拉近匹配对。灵活省显存，但上下文和选项「见面」太晚。
VS

联合编码器（joint-encoder）✅ 本文选择

问题 + 全部选项 + 答案提示打包进同一条序列，一次前向传播。更吃 GPU 显存（序列更长），但更快、架构更灵活。

③ 抽取表示

每个选项取「该选项最后一个内容 token」的隐藏状态，再取序列最后一个 token 的表示——因果 LM 本来就会在末位为「预测下一个 token」积累完整信息。

🎯 自测四题（点开看答案）

为什么因果 LM 微调出的选项打分器会「换序即翻车」？
两个机制叠加：① 因果注意力让靠后的选项能看到靠前的选项（特权信息随位置增加）；② 位置编码让每个 token 的表示携带座次信息。两者都随排列顺序改变，所以隐藏状态、logit 全都跟着变。
把骨干换成 BERT（双向注意力）能根治吗？
不能。双向化解决了「看不到」，但位置编码仍在——token 换个位置，隐藏状态照样变。数据增强（训练时随机打乱选项）也只是统计补丁，不改变机制性偏置。
本文让每个选项「以为自己紧跟在问题后面」，具体改了什么？
位置 ID：问题正常计数，每个选项都从问题结束后的第一个位置重新开始数（三选项 ID 完全重叠）；答案 token 在选项之后继续计数。配套的注意力掩码剪掉选项之间的边，问题段保持因果，答案 token 看全部。
为什么这套掩码方案对 Qwen 特别友好？
因为剪边之后每个 token 依然只往前看——因果性没被破坏，模型不需要学新的注意力范式，预训练能力可以整体继承，只需 LoRA 适配。
🥚 彩蛋：为什么叫 System One？——这个名字借自卡尼曼《思考，快与慢》的双系统理论：System 1 快而直觉（一次前向传播出全部概率），System 2 慢而审慎（逐 token 生成、边想边写）。Jev 做的事，就是给大模型装一个「快思考」的出口。（延伸联想，非原文内容）
